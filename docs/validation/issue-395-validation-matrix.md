## AUTH-K01 Authorization Ownership And Migration Inventory

The controller rows above remain the sole HTTP manifest. Every row explicitly carries a fail-closed AUTH-K01 inventory: owner (`identity`, `platform-reference-data`, `training-planning`, `workout-progress`, `coaching`, `nutrition`, `reporting`, or `notifications`), action category, collection scope, sensitive response/replay disposition, and one or more named AUTH migration tasks. This records current contracts and migration ownership only; `future-replay-review` is an explicit AUTH-K05 gap, while `generic-idempotency-foundation-complete` records the completed scoped-key, snapshot, duplicate-recovery, and no-rerun foundation separately from owner policy work.

- `operation` is the current endpoint effect: `read`, `create`, `update`, `delete`, `command`, or `authentication`; it does not prescribe the future policy implementation.
- `collection scope` identifies the fact that bounds access: `public`, current `actor`, `resource-owner`, active `relationship`, `admin`, authenticated `global`, an `opaque-capability`, or a non-user-facing `technical` boundary. A scope can coexist with richer legacy `access class` and `access facets` evidence.

Maintenance authorization remains deliberately narrow. Internal jobs receive only their persisted technical identifier and optional cancellation token, then delegate to the owning service; they do not acquire an actor, `System`, `Admin`, or cross-owner data bypass. The Hangfire dashboard runs after authentication and `UserContextMiddleware`, requires a currently valid account/session, and delegates its sole `AdminAccess` decision to Identity's current permission evaluator. Stale JWT role or permission claims cannot grant access, and dashboard authorization does not authorize Worker payload processing.

Environment limits are explicit. Testing-host requests prove Swagger and Hangfire middleware are absent, while the generated Swagger document is the executable positive contract; live Development Swagger middleware still requires a prepared non-Testing runtime environment. PostgreSQL restart/retry, concurrency, and failed-save evidence requires `LGYM_TEST_POSTGRES`; the fast in-memory suite proves accepted report progress remains processable after unlink but does not replace relational durability evidence.
