# LgymApi.IntegrationTests.csproj

- Purpose: end-to-end API tests.
- Contains: `WebApplicationFactory`, middleware/auth/serialization/localization coverage, and test persistence.
- API host characterization resolves the real `Program` options and exercises authentication/localization pipeline behavior without changing production composition.
- Authentication integration coverage verifies a current persisted permission decision for stale-token demotion, account block and session revoke, mismatched account/session pairs, and legitimate multi-role actors.
- Rules: reuse integration helpers, prefer NSubstitute mocks for touched collaborators, and validate legacy contract compatibility for changed endpoints.
- Boundary: keep these tests at the API boundary, not unit-test scope.
- `TrainerDashboardTests` exercises both account and trainer history HTTP routes against stored boundary rows (inclusive start/exclusive end), legacy UTC-day queries, local DST/fractional-offset days, foreign-account isolation, and malformed/incomplete/mixed request bodies. `TrainingTests` includes registration and the Warsaw midnight-crossing workout reproduction.
- API startup coverage resolves the canonical AppConfig, enum lookup, and unit-conversion services alongside the command registry/dispatcher, the exact 25 Application and 3 Notifications API-adapter contracts, Identity password scheduler adapter, testing no-op push scheduler, and Notifications FCM provider from the real host composition.
- PostgreSQL lifecycle tests require `LGYM_TEST_POSTGRES`; their disposable factory migrates and seeds a unique leased database, then force-drops it during async disposal. Factory initialization rethrows the original failure after successful cleanup; if cleanup also fails, a redacted exception retains initialization as the primary cause and cleanup as correlated diagnostics. The sealed InMemory factory remains the default fast harness when the variable is absent.
- Run the complete IntegrationTests project, including PostgreSQL cases, with `pwsh -File scripts/run-postgresql-integration-tests.ps1`. The runner requires either Docker or an admin connection through `-ConnectionString`, scopes `LGYM_TEST_POSTGRES` to its process, applies no test-category filter by default, rejects TRX results with unexecuted cases, removes a runner-owned Docker container, and restores the prior process variable. `-TestFilter` is available only for an explicitly documented focused slice and never substitutes for the unfiltered PostgreSQL suite. The leased database factory drops each `lgym_it_*` database during disposal.
- PostgreSQL transaction tests prove Application-owned commit visibility and rollback cleanup from fresh contexts. They do not assign commit or transaction ownership to repositories.
- `PostgreSqlReportingProgressOutboxTests` covers three HTTP submissions through dispatch/delivery, receipt replay, provider-unique consumer and `IActionMessageJob` races, fresh-scope loser retry, exact offset-normalized measurement fidelity, and failed-save cleanup followed by a fresh retry. `PostgreSqlRecurringReportMigrationTests` migrates an isolated database from the immediately previous migration and verifies report/measurement preservation plus the receipt table's unique index. These relational cases require the PostgreSQL runner; the in-memory host cannot prove unique-index, migration, or transaction behavior.
- `ReportingProgressOutboxInMemoryTests` safely drives three HTTP submissions through committed-intent dispatch, action delivery, persisted receipt/measurement readback, and sequential replay without duplicates. It is functional harness evidence only and does not prove relational atomicity, uniqueness races, migrations, or concurrency.
- PostgreSQL tutorial registration coverage verifies credential and Google account creation, the immediate `hasActiveTutorials=true` response, and rollback of tutorial writes with a borrowed registration transaction.
- `PostgreSqlHangfireDurabilityTests` constructs the production non-Testing Hangfire PostgreSQL composition against one leased database, stops and reconstructs the provider around an enqueued `IActionMessageJob`, injects one captured-email failure through the existing `TestEmailSender`, and proves the eventual retry and replay guards without contacting SMTP or FCM.
- The PostgreSQL factory replaces only `AppDbContext`, `DbContextOptions`, `DbContextOptions<AppDbContext>`, and `IDbContextOptionsConfiguration<AppDbContext>`; unrelated EF Core registrations remain intact.
- Both integration factories inherit the production `Program` facade order and seven-assembly mapping set, including Reporting, before applying test overrides. They replace only the shared `AppDbContext` registration set, plus `IEmailSender` and `IPushProviderSender` with singleton captures installed after all module registrations.
- The InMemory factory uses `EnsureCreated`, never runs migrations in the `Testing` environment, and retains `EfUnitOfWork`'s no-op transaction path. The PostgreSQL factory explicitly applies the existing Infrastructure migrations before seeding and retains relational `EfUnitOfWork` transactions.
- `TestEmailSender` and `TestPushProviderSender` prevent test hosts from reaching SMTP or FCM while retaining observable captured attempts; focused tests that need provider outcomes may replace the push capture again through `WithWebHostBuilder` after the factory override.
- Coaching API coverage preserves focused-controller compatibility, legacy payload shapes, authorization, note and invitation behavior, and PostgreSQL replay of canonical and legacy durable envelopes without changing the single-context persistence topology.
- `PostgreSqlCoachingEpisodeTests` uses two-scope barriers so duplicate unlink proves one direct commit plus one recovered completion with a single closure/revision increment, and invitation acceptance proves both writers observed no link before one unique winner. It also covers missing-episode legacy inserts, direct delete, soft-delete closure, identity rewrites, projected start provenance, backfill, and downgrade refusal.
- SignalR coverage uses long-polling `HubConnection` clients against the Testing host to prove two-user recipient isolation and post-event suppression after logout, self-deletion, account blocking, and injected account/session mismatch while an unaffected valid session still receives delivery.
- The endpoint matrix covers the 190-route controller inventory, including the four trainer photo-type routes, with one executable authorization-evidence profile per row. It rejects unresolved evidence and requires each locator to match the route, method, access class, facets, and required evidence categories; Reporting reads that retain source-trainer access across a completed coaching episode use the closed `source-episode-history` facet. Each AUTH-K01 row explicitly declares closed owner, action, collection-scope, response/replay-disposition, and migration-task classifications. The linked technical inventory compares all non-controller Testing-host endpoints and their authorization metadata, dynamically discovers all public Common job interfaces, resolves their registrations, and freezes their entrypoint signatures. Its closed K01 acceptance map resolves every health, Reporting capability, signed development photo, SignalR, Hangfire/Swagger, and Worker entry to positive and negative NUnit behavior; new entries, missing mappings, duplicate mappings, blank evidence, and invalid test locators fail the matrix guard. A mounted HTTP dashboard probe proves current `AdminAccess` succeeds while persisted demotion and session revocation deny the same pre-issued token; Testing still omits dashboard middleware, and prepared PostgreSQL cases remain the relational durability owner.
- `AuthQ01FixtureTests` validates the canonical synthetic fixture and executes real active, unrelated, former, and anonymous HTTP behavior for `GET /api/trainer/trainees/{traineeId}/plans`; the K01 matrix links this test instead of the former parser-only locator. The complete AC01-AC20 policy/case/route/owner/task disposition is in `docs/testing/auth-q01-api-coverage.md`.
- `Microsoft.AspNetCore.SignalR.Client` is centrally pinned and referenced by this test project for the real SignalR clients. It adds no project-reference edge or topology change.
- Integration output links Notifications-owned email templates to the stable `EmailTemplates/<Template>/<en|pl>.email` runtime layout used by the host factories.
- Reporting protocol compatibility coverage verifies protocol 2 is available without a feature flag after startup, capability probes, exact header negotiation, P1/P2 write/read boundaries, dictionary gating, CORS exposure, private no-store responses, and downgrade-safe errors.
- `AuthorizationCapabilitiesContractTests` drives `GET /api/account/access` through the authenticated host, proving fresh Identity policy facts, self-only serialization, private/no-store caching, anonymous denial, and unavailable owner extensions.
- `AuthorizationReplayIntegrationTests` proves a completed trainer-invitation write replays only while current Identity session and permission checks remain valid; it replaces the registered replay port in a Testing host to prove the endpoint's normal authorization succeeds while replay delivery is denied, and verifies no duplicate record is created. It also resolves the registered Identity port against persisted active, revoked, route-mismatched, and demoted account facts.
- Notification source-privacy coverage exercises all nine established in-app types, logical pagination and unread counts after source filtering, valid live SignalR plus queued push creation, and delayed remote-push suppression after a note becomes hidden. It verifies deleted diets, hidden notes, cancelled reports, deleted subjects, stale/missing sources, and current valid sources through the real Testing host without changing delivery keys or deep links.
- `PostgreSqlTutorialRowSecurityTests` uses a disposable leased database and generated maintenance/runtime roles to exercise the tracked staging activation script, parent/child isolation, pool cleanup, denied runtime escalation, and tutorial API parity. `PostgreSqlRuntimeGuardHardeningTests` proves startup rejects incomplete Hangfire privileges and policy semantic drift, while activation rejects altered predicates and a spoofed target environment against the independently stored database marker. The operator checklist is [`tutorial-rls-pilot.md`](../docs/security/tutorial-rls-pilot.md).
- Notification ownership coverage proves cross-account installation/token takeover denial, same-account registration rotation to a currently validated session, exact-pair unregister/disassociate enforcement, legitimate logout disassociation and later rebind, revoked-session provider suppression, source-loss replay denial without duplicate mutation, malformed replay denial, and parity between current-session notification capabilities and the executable API actions. `PostgreSqlPushInstallationTokenUniquenessTests` migrates duplicate tokens to fail-closed tombstones and uses independent-scope save barriers for three relational races: one filtered-token-index winner, one optimistic-concurrency winner when two accounts claim the same disassociated row, and one keyed HTTP token race whose loser returns 403 after targeted change-tracker cleanup while middleware commits both cached 200/403 responses without retrying the failed installation write.
